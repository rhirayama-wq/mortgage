# モゲチェック Loan Checker — Interactive MoC

Request #29 の成果物。経営・営業・プロダクト/UX 評価のために、顧客招待から診断結果共有までを
ブラウザで実際に操作できるデモアプリ（MoC）です。**商用実装ではありません。**

## 1. MoC の目的
- MFS がこの領域へ参入する意義と、TERASS との差別化を画面上で伝える。
- 営業体験（招待の簡単さ・進捗把握・提案への使いやすさ・次アクションの明確さ）を検証する。
- 顧客体験（スマホでの入力しやすさ・本人確認/信用情報利用への不安軽減・結果の分かりやすさ・
  モゲチェック相談への自然な導線）を検証する。
- 将来の商用実装につながる画面構成・入力項目・表示項目を確認する。

## 2. 対象ユーザー（デモ内ロール）
- **不動産営業担当者**: 案件一覧・招待・進捗・診断結果・金融機関比較・改善シミュレーション・相談引継ぎ。
  信用情報の原票・個別契約明細・延滞詳細・内部スコア・eKYC画像・内部審査ロジックは見られない。
- **顧客本人**: 招待リンク想定 → サービス説明 → eKYCデモ → 情報入力 → 同意 → 診断 → 結果 → 相談申込。
- **MFS管理者**: 最小限（デモ案件一覧・診断状態・金融機関マスターのモック・ルールバージョン・監査イベント）。

上部の「ロール切替」タブで営業/顧客/管理者を切り替えられます。

## 3. デモシナリオ（縦一本）
**営業:** ダッシュボード → 「新しい顧客を招待」→ 顧客名/メール/希望価格を入力 → 確認 → 送信
→ 案件が「招待送信済み」→「顧客側デモ画面を開く」→（顧客入力完了後）案件が「診断完了」→
診断結果 → 物件提案方針と次回アクション → モゲチェック相談へ引き継ぐ。

**顧客:** サービス説明 → 本人確認方法選択 → 運転免許証/マイナンバーカードのeKYCデモ →
基本情報（自動入力）確認 → 勤務・収入 → 世帯・共同申込 → 購入希望 → 補足 →
共有/非共有情報の確認と同意 → 診断中 → 診断結果 → 改善シミュレーション → モゲチェック相談申込。

## 4. 画面一覧（route: `/loan-checker`）
営業: `/dashboard`, `/cases`, `/cases/new`, `/cases/[caseId]`, `/cases/[caseId]/result`（最重要）。
顧客: `/customer`, `/customer/identity`, `/customer/profile`, `/customer/employment`,
`/customer/household`, `/customer/property`, `/customer/supplement`, `/customer/consent`,
`/customer/processing`, `/customer/result`（最重要）。
差別化: `/lenders`（最重要）, `/simulations`（最重要）, `/consultation`。
その他: `/admin`, `/errors`（例外画面デモ）。

## 5. 架空データ
- 標準デモケース: 山田 太郎（`taro.yamada@example.test`、38歳・正社員・勤続6年・前年度年収900万円・
  自己資金500万円・希望物件価格8,000万円・希望借入額7,500万円・自動車ローン残高180万円）。
- 診断結果（参考値）: 理論借入上限8,200万円 / 承認見込み6,800〜7,400万円 / 推奨6,300〜6,800万円 /
  購入可能6,800〜7,500万円 / 推奨物件6,800〜7,300万円 / 月額住居費19〜22万円 / 確度「高」 / 有効期限30日。
- 金融機関候補（すべて**架空**）: みらいネット銀行（推奨・変動0.72%）、日本中央みらい銀行（有望・0.85%）、
  さくら地方みらい銀行（可能性あり・0.95%）、住宅金融サポート機構〈架空〉ロング35（有望・長期固定1.80%）。
  - 注: 仕様サンプルの「フラット35」は実在ブランドのため、架空の長期固定商品で代替表現しています。
- 改善シミュレーション3種（自動車ローン完済 / 自己資金+300万円 / ペアローン）。
- 月次KPIはデモ用固定値（招待24・入力開始19・診断完了15・相談移行8・事前審査5・完了率62.5%・移行率53.3%）。
- 集約先: `app/src/lib/loan-checker-moc/`（`types.ts` / `format.ts` / `constants.ts` /
  `calculations.ts` / `fixtures.ts` / `store.tsx`）。

## 6. TERASS との差別化（本MoCで可視化）
1. 銀行タイプ別だけでなく、金融機関・商品単位で判定を提示。
2. 理論借入上限 / 承認見込み額 / 推奨借入額 / 購入可能価格帯を分離表示。
3. 条件改善シミュレーション（現在条件 vs 変更後）を提示。
4. 候補列挙だけでなく、申込順位・申込戦略（第1/第2/バックアップ・推奨順序・注意）を提示。
5. 診断 → モゲチェック相談 → 事前審査 → 融資実行 へつながる導線を提示。

## 7. 商用 MVP との違い（本MoCの位置づけ）
- 診断ロジックは**決定的な簡易計算または固定fixture**であり、本物の審査ロジックではない。
- 状態は**localStorage の架空デモ状態のみ**（token / Cookie / JWT / 実個人情報 / 信用情報 /
  本人確認データは保存しない）。新規DBテーブル・RLS・RPC・migration は追加していない。
- 認証は既存 middleware をそのまま通過するのみ。MoC専用 layout は `requireOrgAccess` を要求しない
  （＝ログイン済みなら閲覧可能な評価用デモ）。

## 8. 未実装事項（本番化で必要）
本物の eKYC / 免許証OCR / マイナンバーカードNFC・JPKI / 信用情報照会 / モゲチェック審査ロジック /
金融機関API / 金融機関別正式判定 / 同意文書の法務確定 / 信用情報の保持・削除 /
不動産会社への共有範囲確定 / モゲチェック相談予約 / 正式な事前審査 / 書類アップロード /
審査進捗 / 融資実行 / 本番監査・セキュリティ / 障害対応 / SLA / 本番データ移行。

## 9. 起動方法
```bash
cd app
npm run dev
# ブラウザでログイン後、 /loan-checker を開く
```
- MoC は認証済みユーザーのみアクセス可能（middleware は変更していない）。
- 依存追加なし。既存の起動手順・スクリプトに変更なし。

## 10. デモ手順（スモーク）
1. `/loan-checker` を開く（入口）。
2. 営業ダッシュボード → 案件一覧 → 「新しい顧客を招待」→ 入力 → 確認 → 送信。
3. 送信完了画面の「顧客側デモ画面を開く」。
4. サービス説明 → eKYCデモ（「読み取りを開始」で進める）→ 基本情報 → 勤務・収入 → 世帯 →
   購入希望 → 補足 → 同意（必須項目にチェック）→ 診断中 → 顧客向け結果。
5. 営業へ戻り、案件詳細 →「営業向け診断結果」。
6. 金融機関・商品比較 → 改善シミュレーション → モゲチェック相談（送信完了）。

## 11. 既知の制約
- 診断結果は参考値であり、正式な事前審査ではない。金融機関の承認を保証しない。
- 処理中画面は固定演出または明示ボタンで進む（ネットワーク障害・APIタイムアウトは再現しない）。
- ページ再読み込みでもデモ継続できるよう localStorage を使用（架空データのみ）。
  営業ナビの「デモデータを初期化」で初期状態に戻せる。
- すべての画面に「デモ・架空データ・未接続・参考値」を常時表示。
